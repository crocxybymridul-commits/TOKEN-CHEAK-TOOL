# Telegram Token Diagnostic Bot

A standalone Python Telegram bot for checking a bot token you own, running 30-second network diagnostics, and exporting JSON/application-log reports.

## Features

- Inline-button dashboard
- Telegram Bot API `getMe` token validation
- Admin-only token testing
- 30-second DNS and HTTPS network sampling
- Current service runtime/deployment indicators
- JSON diagnostic reports
- Recent in-memory application log export
- Submitted tokens are not saved and are not intentionally logged

## Important limitations

- A valid Telegram token does not deploy a bot to Railway.
- This project does not remotely create or deploy another Railway service.
- The deployment screen reports whether **this diagnostic bot's current process** appears to be running on Railway.
- The log export contains this bot's recent application logs, not Railway's complete platform build/deploy logs. Get full platform logs from the Railway project dashboard.
- Do not enter tokens belonging to other people. Token testing is restricted to the configured admin.

## Deploy on Railway

1. Create a new Telegram bot with `@BotFather`.
2. Create a GitHub repository and upload all project files.
3. In Railway, create a project and deploy the GitHub repository as a service.
4. Open **Variables** and add:
   - `BOT_TOKEN`: token for this diagnostic bot itself
   - `ADMIN_USER_ID`: your numeric Telegram user ID
   - `DEV_USERNAME`: developer username, e.g. `@your_username`
   - `APP_NAME`: optional display name
5. Deploy/redeploy. Railway uses `Procfile` / `railway.toml` to start `python main.py`.
6. Open your bot in Telegram and send `/start`.

## Get your numeric Telegram user ID

Use a trusted Telegram user-ID bot or inspect the `from.id` value from an update generated by a bot you control. Do not use a phone number as `ADMIN_USER_ID`.

## Commands

- `/start` — dashboard
- `/help` — help and security information
- `/cancel` — cancel token entry

## Security notes

- Never commit `.env` or tokens to GitHub.
- If a token was exposed, revoke it with `@BotFather` and create a replacement.
- The bot token submitted for testing is held only during the request and is not written to JSON reports or application logs.
- Set `ADMIN_USER_ID`; token testing is disabled for everyone else if it is missing.
